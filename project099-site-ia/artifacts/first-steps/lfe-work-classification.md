# LFE Work Classification

These are categories, rather than priorities or an execution order.

| Group | Central question | Work included |
|---|---|---|
| **1. Evidence and baseline assessments** | What exists, how does it work, and where does it fail? | Full erlang.org IA inventory; lfe.io inventory and candid assessment; historical baggage; documented user difficulties and compatibility failures. |
| **2. Compatibility and version policy** | What does an LFE version promise about Erlang/OTP compatibility? | Supported combinations; minimum/maximum/set semantics; build versus runtime compatibility; older-version support expectations; possible LFE 3.0 transition; machine-readable metadata and schema semantics. |
| **3. Release engineering and distribution** | How do we preserve, identify, validate, and deliver those combinations? | Historical snapshots; static branches; tags and naming; release mappings; precompiled artifacts; packaging; Downloads content and selection mechanisms. |
| **4. Information architecture and content** | How should users find and understand LFE’s resources? | Site hierarchy and navigation; Downloads, Documentation, Books, and Videos; front-page organisation; content consolidation, rewriting, retirement, and version relationships; accommodation of the new documentation format. |
| **5. Design foundations and visual experience** | What coherent design principles should govern the site? | Assessment of your existing design-system work; Material/Carbon/Polaris synthesis; perception, colour, typography, and semantic units; CSS and component foundations; imagery, accessibility, and responsive presentation. A revised or new design system remains an explicit parallel side quest. |
| **6. Experiments and validation** | What evidence would justify choosing one approach over another? | Reproducing build/runtime failures; testing `develop-compiler` against existing code; compatibility matrices; CI ideas; naming and download-selection prototypes; navigation and layout experiments. |
| **7. Scope, decisions, and collaboration** | What have we agreed, what remains open, and who owns what? | Goals and boundaries; questions for Robert; responsibilities; dependencies; provisional decisions and their evidence; eventual plans and reviewable tickets. |
